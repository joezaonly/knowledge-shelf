ประตู 2 ชั้นของ AI Agent — ปิดถามอนุมัติให้ถูกจุด

สั่งปิดโหมดอนุมัติแล้ว แต่พอเริ่มเซสชันใหม่ระบบยังเด้งถามอยู่? คำตอบคือระบบถามยืนยันมี "หลายประตูที่แยกจากกัน" — ปิดประตูเดียวไม่พอ และบางประตูออกแบบมาให้ปิดไม่ได้เลย

🤖 อัปเดต 26 ส.ค. 2026 ⏱️ อ่าน ~7 นาที 🎯 ระดับ: ทำตามได้เลย

1. อาการที่เจอ 🧭

ตั้งค่าให้ AI ไม่ต้องขออนุมัติก่อนรันคำสั่งแล้ว แต่:

  • พิมพ์คำสั่งลัดล้างเซสชัน (เช่น /new, /reset) → ยังเด้งถามยืนยัน
  • ให้ AI เขียนไฟล์บางประเภท (เช่น ไฟล์ตั้งค่าพฤติกรรมของ AI เอง) → ถามทุกครั้ง แม้ปิดโหมดแล้ว

ทั้งสองอย่างนี้ ไม่ใช่บั๊ก — เป็นคนละประตูกับคำสั่งเชลล์ปกติ

2. แผนผังประตูทั้งระบบ 🗺️

ประตูคุมอะไรปิดได้ไหม
1. โหมดอนุมัติคำสั่งเชลล์
approvals.mode		คำสั่งที่ AI รันผ่านเทอร์มินัล (rm, git reset ฯลฯ)✅ ปิดได้: off
2. ยืนยันคำสั่งลัดทำลายล้าง
approvals.destructive_slash_confirm		คำสั่งลัดที่ล้างงาน: /new, /reset, /undo✅ ปิดได้: false
3. ไฟล์สั่งพฤติกรรม AIไฟล์อย่าง AGENTS.md, CLAUDE.md, .cursorrules ที่ "สอน" AI สำหรับทุกเซสชันถัดไป❌ ถามเสมอ ปิดไม่ได้
4. บล็อกคำสั่งหายนะคำสั่งล้างดิสก์ ปิดเครื่อง ลบระบบ — ระดับทำลายล้างถาวร❌ บล็อกถาวร ปิดไม่ได้ แม้โหมด off
🚨 บทเรียนสำคัญ: ประตู 1 กับ 2 เป็นอิสระจากกันโดยสมบูรณ์ — ตั้งค่าประตู 1 เป็น off แล้วประตู 2 ไม่เปลี่ยนตาม ต้องปิดทีละตัว

3. ทำไมประตู 3-4 ปิดไม่ได้ (และทำไมควรดีใจ) 🔒

ไฟล์อย่าง AGENTS.md คือ "คำสั่งที่ AI จะอ่านทุกเซสชันในอนาคต" — ถ้าเว็บที่ AI เปิดอ่านถูกฝังข้อความอันตราย (prompt injection) แล้วหลอกให้ AI แก้ไฟล์นี้ได้ คำสั่งอันตรายจะฝังถาวรข้ามทุกเซสชัน ระบบจึงบังคับถามคนทุกครั้ง:

  • ป้องกัน "คำสั่งฝังถาวร" จากเนื้อหาภายนอก
  • หลักเดียวกันกับ: AI ไม่ควรปิดระบบรักษาความปลอดภัยของตัวเองได้
💡 เจอเด้งถามตอนให้ AI เขียนไฟล์ประเภทนี้ = ทำงานถูกต้องแล้ว ไม่ใช่ความผิดพลาด

4. วิธีตั้งค่าให้ถูกจุด ⚙️

👤 คนทำพิมพ์คำสั่งเอง (หรือสั่งให้ AI รัน) — ตรวจค่าได้ทันที ไม่ต้องรีสตาร์ท:

# ปิดการถามอนุมัติคำสั่งเชลล์ (เทียบเท่าโหมด --yolo)
hermes config set approvals.mode off

# ปิดการยืนยันคำสั่งลัดล้างเซสชัน
hermes config set approvals.destructive_slash_confirm false

# ตรวจค่า
hermes config get approvals.mode                        # ต้องได้ off
hermes config get approvals.destructive_slash_confirm   # ต้องได้ false
✅ ทั้งสองค่าอ่านจากไฟล์ตั้งค่าแบบสด — มีผลทันทีไม่ต้องเริ่มเซสชันใหม่ (ค่าถูกแคชด้วยเวลาแก้ไขไฟล์)

ทางเลือกตรงกลาง (แนะนำถ้าไม่ได้รีบ)

โหมดพฤติกรรม
smart (ค่าเริ่มต้น)คำสั่งปลอดภัยผ่านเอง, อันตรายปฏิเสธ, ไม่แน่ใจถาม
manualถามทุกคำสั่ง
offไม่ถามเลย — แต่ประตู 3 และ 4 ยังทำงานอยู่

5. บทเรียนของจริง 🛠️

ปัญหาสาเหตุวิธีแก้
ปิดโหมดแล้ว /new ยังถามประตูคำสั่งลัดแยกจากโหมดอนุมัติตั้ง destructive_slash_confirm: false เพิ่ม
ตั้ง mode: off ใน YAML แล้วกลายเป็น falseYAML แปลคำว่า off เป็น booleanใส่เครื่องหมายคำพูด: mode: 'off' หรือใช้ hermes config set
AI เขียน AGENTS.md แล้วถาม ทั้งที่ปิดโหมดแล้วไฟล์สั่งพฤติกรรมถูกปกป้องเสมอไม่ต้องแก้ — กดยืนยันได้ เป็นไปตามออกแบบ
คำสั่งล้างดิสก์ถูกบล็อกแม้ --yoloบล็อกคำสั่งหายนะเป็นชั้นล่างสุดรันเองในเทอร์มินัลถ้าจำเป็นต้องทำจริง
อยากรู้ว่าใคร/อะไรถามดูที่ข้อความ: เชลล์ = ประตู 1, /new = ประตู 2, ไฟล์ .md = ประตู 3แก้ให้ถูกประตู

6. เช็กลิสต์ "ไม่ต้องถามอีกเลย" 📋

✅ ต้องการลื่นไหลสูงสุด:
1. approvals.mode = off
2. approvals.destructive_slash_confirm = false
3. ยอมรับว่าไฟล์สั่งพฤติกรรม (AGENTS.md ฯลฯ) จะยังถาม — นี่คือความปลอดภัยขั้นต่ำที่เหลืออยู่

ให้ AI ยืมจอจริงของคุณ — เปิดบราวเซอร์บนหน้าจอผู้ใช้
ให้ล็อกอินเอง แล้ว AI คุมที่เหลือ

งานที่ต้องล็อกอินเว็บ (ใส่รหัสผ่าน, 2FA) แต่อยากให้ AI ควบคุมต่อ: สูตรเปิด Chrome บนจอจริงของผู้ใช้ผ่าน CDP โดยผู้ใช้พิมพ์รหัสเอง ไม่ต้องใช้ VNC หรือจอเสมือนให้ยุ่งยาก

🤖 อัปเดต 26 ส.ค. 2026 ⏱️ อ่าน ~10 นาที 🎯 ระดับ: ทำตามได้เลย

1. ปัญหาที่ต้องแก้ 🧭

AI agent ต้องทำงานกับเว็บที่ต้องล็อกอิน (เช่น สร้างวิดีโอด้วย AI, จัดการบัญชี) แต่:

  • AI ไม่ควรรู้รหัสผ่านของผู้ใช้
  • ผู้ใช้ต้องพิมพ์รหัสเอง หรือยืนยัน 2FA ด้วยตัวเอง
  • หลังจากล็อกอินแล้ว อยากให้ AI ควบคุมต่อทั้งหมด
🚨 อย่าให้ AI พิมพ์รหัสผ่านแทนผู้ใช้ — ถ้ามี 2FA ก็ทำไม่ได้ด้วย และเป็นการเก็บข้อมูลอ่อนไหวโดยไม่จำเป็น

2. วิธีที่ผิด (เคยทำแล้ว) ❌

🤖 AI ทำเปิดบราวเซอร์แบบ "ลอย" บนจอเสมือน:

แนวทางปัญหา
เปิด Chrome บน Xvfb (จอเสมือน)ผู้ใช้ไม่เห็นอะไร — ต้องต่อด้วย VNC เพิ่ม
ทำ VNC tunnel ให้ผู้ใช้เข้าผ่านลิงก์ซับซ้อน, ต้องแชร์รหัส, เสี่ยงถ้าลิงก์หลุด
เปิดบนจอจริงแต่ใช้โปรไฟล์หลักChrome บล็อก --remote-debugging-port บนโปรไฟล์หลัก

3. วิธีที่ถูก: เปิดบนจอจริง + โปรไฟล์แยก ✅

👤 คนทำแค่เปิดเทอร์มินัลรันคำสั่งเดียว (หรือให้ AI รันให้) · 🤖 AI ทำที่เหลือทั้งหมดผ่าน CDP

ขั้น 1: หา display จริงของผู้ใช้

# ดูว่าใครล็อกอินอยู่ที่จอไหน
loginctl list-sessions --no-legend
# ผลลัพธ์จะมีชื่อผู้ใช้ + ประเภท (x11 / wayland)

# หา DISPLAY และ XAUTHORITY ของผู้ใช้คนนั้น
# (ตัวอย่าง: ผู้ใช้ชื่อ "someone" ล็อกอินอยู่ที่ :0)
DISPLAY=:0
XAUTHORITY=/run/user/1000/gdm/Xauthority   # เลข 1000 = UID ของผู้ใช้

ขั้น 2: เปิด Chrome ในนามผู้ใช้จอ + โปรไฟล์แยก

sudo -u someone env \
  DISPLAY=:0 \
  XAUTHORITY=/run/user/1000/gdm/Xauthority \
  DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus \
  google-chrome \
    --no-first-run --no-default-browser-check \
    --remote-debugging-port=9222 \
    --user-data-dir=/home/someone/.chrome-automation \
    --window-size=1600,1000 \
    about:blank
💡 --user-data-dir สำคัญมาก — Chrome ไม่ยอมเปิด remote debugging บนโปรไฟล์หลัก (default profile) เพื่อความปลอดภัย ต้องชี้ไปที่ไดเรกทอรีแยก
🚨 ถ้าไม่มี --user-data-dir Chrome จะขึ้น: DevTools remote debugging requires a non-default data directory แล้วไม่เปิด port 9222

ขั้น 3: ตรวจว่า CDP พร้อม

# ตรวจว่า Chrome เปิด port 9222 แล้ว
curl -s http://127.0.0.1:9222/json/version | head -3
# ต้องเห็น: "Browser": "Chrome/..." + "Protocol-Version"

ขั้น 4: ให้ผู้ใช้ล็อกอินเองบนจอ

หน้าต่าง Chrome จะปรากฏบนจอจริงของผู้ใช้ — พิมพ์อีเมล รหัสผ่าน ยืนยัน 2FA ได้เลย ส่วน AI รออยู่เฉยๆ ไม่ต้องยุ่ง

ขั้น 5: AI เชื่อมต่อและทำงานต่อ

# AI เชื่อมต่อผ่าน CDP (port 9222) แล้วสั่งงานได้เลย
# เช่น เปิดหน้าอื่น, กดปุ่ม, พิมพ์, อ่านข้อความบนหน้า

4. สูตรย่อ: สิ่งที่ต้องจำ 📋

รายการค่า
Display ของผู้ใช้:0 (ตรวจด้วย loginctl)
XAUTHORITY/run/user/<UID>/gdm/Xauthority
Remote debugging port9222 (หรือเลขอื่นที่ว่าง)
User data dirต้องเป็นโฟลเดอร์แยก — ห้ามใช้โปรไฟล์หลัก
ใครพิมพ์รหัสผ่าน👤 ผู้ใช้เอง บนจอจริง
ใครคุมหลังจากนั้น🤖 AI ผ่าน CDP

5. บทเรียนของจริง 🛠️

ปัญหาสาเหตุวิธีแก้
Chrome ไม่เปิด port 9222ใช้โปรไฟล์หลัก (default)เพิ่ม --user-data-dir=/path/to/separate
เปิด Chrome แล้วจอดำ/ไม่เห็นไม่ได้ส่ง DISPLAY หรือ XAUTHORITYส่งทั้ง DISPLAY=:0 และ XAUTHORITY=...
เปิดในนาม root แต่จอไม่ขึ้นรันเป็น root ไม่ได้ใช้ session ของผู้ใช้ใช้ sudo -u <user> env DISPLAY=...
อยากทำแบบ headless (ไม่มีจอ)งานนี้ต้องมีจอให้ผู้ใช้ล็อกอินใช้จอเสมือน (Xvfb) + VNC แทน — แต่ซับซ้อนกว่า
Chrome ขึ้น "Allow remote debugging?"Chrome เวอร์ชันใหม่ถามยืนยันคลิก Allow บนจอ หรือใช้โปรไฟล์แยก (ไม่มี popup)

6. ส่วนไหนคนทำ / ส่วนไหน AI ทำ 🧩

ขั้นงานใครทำเวลา
1หา display + เปิด Chrome ด้วยคำสั่ง🤖 AI (หรือ 👤 รันเอง)1 นาที
2ล็อกอินเว็บ: พิมพ์รหัส, ยืนยัน 2FA👤 คน (บนจอจริง)1-3 นาที
3แจ้งว่าล็อกอินเสร็จแล้ว👤 คน (พิมพ์บอก)—
4เชื่อมต่อ CDP + ทำงานต่อทั้งหมด🤖 AIตามงาน
5ตรวจผลลัพธ์บนจอ👤 คนตามงาน
✅ ผลลัพธ์: ผู้ใช้พิมพ์รหัสเอง (ปลอดภัย) · AI ทำงานต่อทั้งหมด (อัตโนมัติ) · ไม่ต้องทำ VNC หรือจอเสมือน · โปรไฟล์บราวเซอร์แยกไม่กระทบข้อมูลหลักของผู้ใช้

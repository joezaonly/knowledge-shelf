ทำให้ AI "จำได้ไม่ลืม"
ระบบความจำ 4 ชั้นที่แชร์ข้ามเครื่อง

สถาปัตยกรรมที่ใช้กับ AI Agent หลายเครื่องพร้อมกัน — แก้ปัญหาเสร็จครั้งเดียว ทุกเครื่องเรียนรู้ตามได้ทันที ผ่าน Git ที่ซิงก์อัตโนมัติ

🤖 อัปเดต 25 ส.ค. 2026 ⏱️ อ่าน ~10 นาที 🎯 ระดับ: วางระบบตามได้เลย

1. ทำไมต้อง "หลายชั้น" 🤔

AI Agent สมัยใหม่มีความจำสองแบบที่มักถูกใช้ผิดที่: ความจำระยะสั้น (ในบทสนทนา — หายเมื่อเริ่มแชตใหม่) กับ ความจำถาวร (จำกัดมาก ~2,000 ตัวอักษร) ถ้าโยนทุกอย่างลงความจำถาวรจะเต็มทันที ถ้าพึ่งแต่แชตก็ลืมทุกครั้งที่เริ่มใหม่

คำตอบคือ แยกข้อมูลเป็นชั้นตามหน้าที่ — แต่ละชั้นมีขนาดและจุดประสงค์ต่างกัน แล้วให้ชั้นเล็กชี้ไปหาชั้นใหญ่

2. ระบบ 4 ชั้น 🏗️

Layer 1: ความจำถาวร (Memory)

~2,200 ตัวอักษร · โหลดทุกเทิร์น

ข้อเท็จจริงสำคัญที่ต้องใช้ตลอด: เจ้าของคือใคร ชอบอะไร เครื่องนี้ทำหน้าที่อะไร + ตัวชี้ไปคลังความรู้ — เก็บเฉพาะ "กุญแจ" ไม่เก็บ "ของ"

Layer 2: ทักษะ (Skills)

ไม่จำกัด · โหลดเมื่อเจองานตรงประเภท

"วิธีทำ" ที่พิสูจน์แล้ว — เขียนหลังแก้ปัญหาสำเร็จ (5+ ขั้นตอน) มีเงื่อนไขทริกเกอร์ คำสั่งแม่นยำ จุดที่มักพลาด และวิธีตรวจสอบ

Layer 3: คลังความรู้ (Knowledge Base — Git repo)

ไม่จำกัด · แชร์ข้ามเครื่องผ่าน Git

"เกิดอะไรขึ้น" ฉบับละเอียด — โน้ตแก้ปัญหาทุกเคส สเปกเครื่อง ดัชนีปัญหา ตารางการตัดสินใจ ซิงก์อัตโนมัติทุก 30 นาที

Layer 4: ค้นหาบทสนทนาเก่า (Session Search)

ไม่จำกัด · ค้นย้อนหลังอัตโนมัติ

บทสนทนาเต็มทุกเซสชันเก็บในฐานข้อมูล ค้นหาได้ด้วยข้อความ — ใช้กู้บริบทเก่าที่ลืมจด

3. โครงสร้างคลังความรู้ที่แนะนำ 📁

knowledge/                     ← Git repo (private) — ซิงก์ทุก 30 นาที
├── Home.md                    ← หน้าแรก: ภาพรวม + ตารางเครื่อง
├── problems/Problem Index.md  ← ดัชนี: ปัญหา → อาการ → วิธีแก้ → ลิงก์โน้ต
├── machines/<hostname>.md     ← สเปก + ประวัติปัญหาของแต่ละเครื่อง
├── solutions/
│   ├── <machine>/             ← โน้ตแก้ปัญหาเฉพาะเครื่อง (เขียนลงชื่อเครื่องตัวเอง)
│   └── shared/                ← วิธีที่ใช้ได้กับทุกเครื่อง
├── decisions/                 ← การตัดสินใจสำคัญ + เหตุผล
├── registry/                  ← machines.json + heartbeat (ใครออนไลน์ล่าสุด)
├── scripts/                   ← สคริปต์ซิงก์/บูตสแตรป (เครื่องใหม่โคลนแล้วรันได้เลย)
└── templates/                 ← เทมเพลตโน้ตแก้ปัญหา (บังคับใช้ — กันลืมหัวข้อ)

เทมเพลตโน้ตแก้ปัญหา (บังคับใช้ทุกเคส)

ทุกโน้ตต้องมี: อาการ → สาเหตุ → วิธีแก้พร้อมคำสั่งที่ใช้จริง (copy-paste ได้) → คำสั่งตรวจสอบ → Rollback (ถ้าแก้ค่าระบบ) → ผลลัพธ์ ตัวเลขก่อน/หลัง

4. ทำให้หลายเครื่องแชร์กัน 🔁

องค์ประกอบวิธีทำ
แหล่งกลางGit repo private บน GitHub (เครื่องอื่นเข้าถึงผ่าน SSH key)
ซิงก์อัตโนมัติcron ทุก 30 นาที: git pull --rebase ก่อน → มีของใหม่ค่อย commit+push (เงียบเมื่อไม่มีอะไรเปลี่ยน)
กันชนกันกฎ: เครื่องใครเครื่องมัน — เขียนลงโฟลเดอร์ชื่อเครื่องตัวเองเท่านั้น, โฟลเดอร์ shared แก้ไขระวัง
ตัวชี้วัดชีพheartbeat JSON ต่อเครื่อง — ดูได้ว่าเครื่องไหนซิงก์ล่าสุดเมื่อไหร่
หน้าจอคน (ทางเลือก)mirror ไป Notion ให้อ่านง่ายผ่านมือถือ — ตั้งให้ซิงก์จาก "เครื่องเดียว" กันเขียนซ้ำ

5. กฎเหล็กของระบบ ⚖️

  • แก้ปัญหาเสร็จ → เขียนทันที (ไม่รอให้สั่ง) + อัปเดตดัชนีปัญหาทุกครั้ง
  • ข้อมูลส่วนตัว/โทเค็น/รหัสผ่าน → ห้ามลงคลังเด็ดขาด เขียน [REDACTED] แทน
  • ทักษะเก็บ "วิธีทำ" · คลังเก็บ "ข้อมูล" · ความจำถาวรเก็บ "ตัวชี้" — ห้ามปน
  • ก่อนแก้ปัญหาใหม่ → ค้นดัชนีปัญหาก่อนเสมอ อาจเคยแก้แล้ว
  • USER.md (ข้อมูลเจ้าของ) เหมือนกันทุกเครื่อง · MEMORY.md (ข้อมูลเครื่อง) เครื่องใครเครื่องมัน
🚨 บทเรียนจริง: เคยมีเครื่องเก่าเขียนความรู้ลงพาธที่ไม่ได้ซิงก์ → ความรู้ "หายไป" เพราะไม่มีเครื่องไหนเห็น ตั้งแต่วันนั้นจึงระบุพาธเดียวตายตัวในเอกสาร + ตรวจพาธเก่าตกค้างเป็นขั้นตอนบังคับของเครื่องใหม่

6. บูตสแตรปเครื่องใหม่ในสคริปต์เดียว 🚀

เครื่องใหม่เข้าร่วมระบบด้วย bootstrap.sh ตัวเดียว: สร้าง SSH key → ให้เพิ่มคีย์เข้า GitHub → โคลนคลัง → ตั้งค่า cron → อัปเดต registry → ทดสอบซิงก์ → รายงานผล รวม ~10 นาทีจากเครื่องเปล่าเป็นสมาชิกเต็มตัว

✅ ผลลัพธ์ที่ได้: เครื่องใหม่แก้ปัญหาคืนนี้ เครื่องอื่นเรียนรู้ได้ภายใน 30 นาที — ความรู้ของระบบเติบโตแบบทบต้น ไม่มีวันลืมอีก
